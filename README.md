# YouTube Downloader

Версия **1.0.1**, отдельная консольная редакция от 2 октября 2026 года.
Запуск после установки зависимостей: **start.cmd**. В локальной сборке готовый EXE находится в `dist/YouTubeDownloader`.
Исходники лежат рядом с этим файлом. Расширение браузера для работы не требуется.

Репозиторий содержит исходники: папки `dist`, `build`, окружение `.venv` и
личные cookies/настройки не отправляются в Git. После клонирования запустите
`setup.cmd`, установите FFmpeg и Node.js согласно разделу ниже, затем `start.cmd`.
Готовая переносимая сборка, если опубликована, находится в разделе **Releases**.

## Установка из GitHub

Скачайте **Code → Download ZIP** и распакуйте архив, либо выполните:

```powershell
git clone https://github.com/Fousman34/ConsoleDownloader.git
cd ConsoleDownloader
```

На Windows установите Python 3.10 или новее с Python Launcher, FFmpeg и Node.js:

```powershell
winget install --id Python.Python.3.13 --exact
winget install --id Gyan.FFmpeg --exact
winget install --id OpenJS.NodeJS.LTS --exact
```

Откройте новый терминал, чтобы обновился PATH, затем в папке проекта запустите
`setup.cmd` и `start.cmd`. Проверка: `start.cmd --doctor`.
Для исходников Python обязателен; EXE и сторонние исполняемые файлы не входят
в архив исходников GitHub.

На Linux/macOS с установленными Python 3.10+, FFmpeg и Node.js:

```sh
python3 -m venv .venv
. .venv/bin/activate
python -m pip install -r requirements.txt
python main.py --doctor
python main.py
```

Лицензии сторонних компонентов перечислены в `THIRD_PARTY_NOTICES.md`.

Небольшие изменения: единая мятная тема меню и прогресса, папка и качество
видны прямо в главном меню, загрузка сегментов идёт до трёх одновременно,
обновление прогресса ограничено восемью кадрами в секунду.

Готовое консольное приложение для Windows с русским и английским интерфейсом.
Меню управляется стрелками; Enter выбирает пункт, Tab дополняет путь.

## Быстрый запуск

**На этом компьютере:** дважды нажмите `start.cmd` в папке проекта.

**Без Python:** откройте `dist/YouTubeDownloader/YouTubeDownloader.exe`.
В сборку входят Python, библиотеки, ffmpeg, ffprobe и Node.js. Папку можно
перенести целиком на другой Windows x64 компьютер. Не перемещайте один EXE
отдельно от `_internal` и `tools`. Нужны Windows 10/11 x64 и интернет.

Настройки: меню → Настройки. Первое открытие предлагает выбрать язык.
По умолчанию файлы сохраняются в `Downloads/YouTube` вашего пользователя.

## Скачивание

1. Выберите «Скачать видео».
2. Вставьте ссылку на обычное видео, Shorts, запись трансляции или youtu.be.
3. Выберите 360p, 480p, 720p, 1080p, 1440p, 2160p, лучшее качество или MP3.
4. Дождитесь загрузки и обработки. Панель покажет путь к итоговому файлу.

Число означает **верхнюю границу высоты**, а не обещание точного разрешения.
Если доступно только меньшее качество, будет выбрано оно. Если подходящего
формата нет, появится ошибка; приложение не переключится на более высокое качество.
В вертикальных Shorts граница также относится к высоте кадра.

Раздельные видео и аудио объединяются в **MKV**, без перекодирования и потери
качества: контейнер совместим с кодеками YouTube. Если источник уже содержит
звук, файл может остаться MP4/WebM. MP3 конвертируется в 192 кбит/с;
это не повышает качество исходного аудио.

Имя включает название, ID ролика и выбранное качество. Разные режимы не
мешают друг другу. Существующие файлы не перезаписываются; `.part` позволяют
продолжить прерванную загрузку при повторном запуске с теми же параметрами.
Поддерживается один ролик за раз; параметр плейлиста в ссылке игнорируется.
Ctrl+C во время скачивания отменяет его и возвращает в меню; в остальных
диалогах завершает программу.

## Командная строка

PowerShell из папки проекта:

```powershell
.\dist\YouTubeDownloader\YouTubeDownloader.exe --doctor
.\dist\YouTubeDownloader\YouTubeDownloader.exe "https://youtu.be/VIDEO_ID" --quality 1080 --folder "D:\Видео"
.\dist\YouTubeDownloader\YouTubeDownloader.exe "https://youtu.be/VIDEO_ID" --quality mp3 --lang ru
```

Замените `VIDEO_ID` на настоящий ID из 11 символов или передайте полную ссылку.
Доступны `--help`, `--version`, `--proxy`, `--cookies`, `--lang ru|en`.
Параметры командной строки действуют на один запуск и не меняют настройки.
В режиме командной строки код возврата: 0 — успех, 1 — ошибка, 2 — нет
интерактивного терминала для меню, 130 — отмена Ctrl+C.

## Установка из исходников

Нужен **Python 3.10+** (проверено на 3.13). В исходной инструкции неверно
указан Python 3.9: использованный синтаксис и современный yt-dlp требуют 3.10+.

На Windows запустите `setup.cmd`. Он создаёт `.venv`, устанавливает библиотеки
и проверяет системные инструменты. Если инструментов нет:

```powershell
winget install --id Gyan.FFmpeg --exact
winget install --id OpenJS.NodeJS.LTS --exact
```

После системной установки откройте новый терминал. Нужны ffmpeg и ffprobe,
а также Node.js 22+ или Deno 2.3+. Node.js включается приложением явно.
Пакет `yt-dlp[default]` устанавливает необходимые EJS-скрипты.
Актуальные требования: [yt-dlp EJS](https://github.com/yt-dlp/yt-dlp/wiki/EJS).

Ручная установка Windows:

```powershell
py -3 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe main.py --doctor
.\.venv\Scripts\python.exe main.py
```

Linux/macOS: создайте venv через `python3 -m venv .venv`, используйте
`.venv/bin/python`; установите ffmpeg и поддерживаемую JS-среду средствами
вашей системы. Исходники рассчитаны на эти платформы, но сборка и проверки
в этом проекте выполнены на Windows.

## Прокси и cookies

В настройках можно указать свой HTTP/SOCKS прокси, например
`http://127.0.0.1:8080` или `socks5://127.0.0.1:1080`. Пустая строка отключает его.
Приложение не предоставляет прокси-сервер.

Для роликов, требующих входа, можно указать свой файл `cookies.txt` в формате
Netscape. Он должен существовать и содержать действующую сессию YouTube.
Автоматического чтения браузера нет. Cookies содержат секреты: не отправляйте
их другим людям. Прокси, включая пароль в адресе, хранится в настройках обычным
текстом. Эти функции не гарантируют доступ к удалённым или запрещённым роликам.

## Настройки и ошибки

Файл настроек: `~/.ytdl_config.json` (Windows: `%USERPROFILE%\.ytdl_config.json`).
Для отдельного профиля задайте переменную окружения `YTDL_CONFIG`.
Сохранение атомарное; ошибки записи показываются пользователю. Если JSON
повреждён, программа сообщает об этом и использует значения по умолчанию.
Последующее сохранение настроек заменит повреждённый файл.

| Проблема | Решение |
| --- | --- |
| Не запускается меню | Откройте `start.cmd` в обычном терминале Windows Terminal/PowerShell |
| Не найден ffmpeg/JS | Запустите `--doctor`; используйте полную готовую папку или установите инструменты |
| 403, тайм-аут, ограничение сети | Проверьте доступ к YouTube, при необходимости настройте свой прокси |
| Вход/возрастные ограничения | Укажите свой действующий Netscape cookies.txt |
| Signature / unable to extract | Обновите зависимости; для EXE затем пересоберите приложение |
| Формат недоступен | Выберите другое качество или «Лучшее доступное» |

Обновление исходников:

```powershell
.\.venv\Scripts\python.exe -m pip install --upgrade -r requirements.txt
```

Обновление пакетов в `.venv` **не обновляет уже собранный EXE**. После него
запустите сборку. YouTube меняется, поэтому нельзя гарантировать скачивание
каждого ролика и постоянную работоспособность без обновлений.

## Проверки и сборка

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
powershell -NoProfile -ExecutionPolicy Bypass -File .\build.ps1 -Zip
```

Для сборки нужны ffmpeg, ffprobe и Node.js в PATH. Скрипт создаёт
`dist/YouTubeDownloader` и, с `-Zip`, архив `dist/YouTubeDownloader-Windows-x64.zip`.
`requirements-lock.txt` фиксирует проверенные версии; для воспроизведения
установите его вместо `requirements.txt` в отдельное окружение.

После установки только `requirements.txt` добавьте средство сборки:
`.\.venv\Scripts\python.exe -m pip install pyinstaller`.
Запуск тестов после установки зависимостей:

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

На Linux/macOS используйте `.venv/bin/python` вместо пути Windows.
